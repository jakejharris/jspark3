Cadence adds the measured QKV INT8 decode shadow and request-local
speculative width controller to the three-DGX-Spark recipe. It carries the
long-context kernel disable and the fabric documentation correction from
v1.0.1. It changes no checkpoint, model config, or tokenizer in this mirror.
The GitHub tag binds the release content; the Hub documentation update is a
separate publication operation.

## Integrated live verification

The full verifier passed on candidate `a729583` with host verifier
`456a262`: all-rank runtime/image identity and safety, Cadence capture,
load, health, arithmetic, focused witness, and strict long-context witness.
The pinned long-context request reported **48,957 prompt tokens and 51
completion tokens**, with the codeword returned verbatim. The
[sanitized receipt](https://github.com/jakejharris/jspark3/blob/v1.1.0/results/evidence/candidate/cadence-v11/LIVE-VERIFY.json)
and [provenance](https://github.com/jakejharris/jspark3/blob/v1.1.0/results/evidence/candidate/cadence-v11/README.md#integrated-live-verification)
separate the running candidate from its host verifier and retain prior
refusals. The final package keeps those tested recipe bytes; it has not been
cold-boot tested as an archive.

This request proves operation past the old single-stream boundary. It does
not certify the configured maximum context, sustained concurrency, or an
independent fleet. The focused witness measures only its fixed admission
workload; it is not a Pi performance claim. Historical benchmark populations,
failed sham controls, non-replicated code gains and candidate-only quality
failures remain unchanged. Separate experiments supply no release evidence.
